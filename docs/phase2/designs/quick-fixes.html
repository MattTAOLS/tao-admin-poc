5The colour comes from each covenant's own kind field, which every covenant object already carries: ceiling (a max test, lower is better), floor (a min test, higher is better) or binary (yes / no, no trend). The data has no field called "direction"; kind is it. Ceiling + rising = red, ceiling + falling = green, floor + rising = green, floor + falling = red, flat = grey, n/a = grey "n/a". No metric-name lists, no new data.
6The word stays "Rising" / "Falling" / "Flat"; colour is never the only signal. Screen readers and the tooltip add "better" or "worse". The "Test" and "Last period" columns New are optional: they show why a colour was chosen (last period values are the real prior_covenants). Drop them if the table gets too wide; the colour rule does not need them.

So a breached covenant can carry a green arrow (Finloc delinquency 10.47% → 8.83%, still above 8%). A ceiling ratio that is negative and rising toward zero (TPine net recoveries shrinking) is red.
